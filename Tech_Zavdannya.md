# Технічне завдання

## 1. Мета і завдання продукту

**Мета:** створити вебзастосунок на PHP, який замінює ручний облік товарів у невеликому магазині та допомагає вчасно поповнювати запаси.

**Завдання:**
- вести каталог товарів;
- фіксувати кожне надходження та списання/продаж товару;
- забезпечити швидкий пошук, фільтрацію та сортування товарів;
- формувати звіти та статистику по залишках;
- автоматично рекомендувати, які товари і в якій кількості варто замовити.

**Користувачі:** продавець/комірник (щоденні операції зі складом), власник магазину (звіти, рішення про закупівлі).

## 2. Функціональні вимоги

| ID | Вимога |
|---|---|
| FR-1 | Додавання, редагування та видалення карток товарів |
| FR-2 | Реєстрація надходження товару на склад |
| FR-3 | Реєстрація списання/продажу з контролем: не можна списати більше, ніж є в наявності |
| FR-4 | Пошук за назвою/SKU, фільтрація за категорією та постачальником, сортування |
| FR-5 | Зведений звіт: кількість позицій, вартість запасів, товари з низьким залишком |
| FR-6 | Автоматичні рекомендації щодо поповнення запасів на основі швидкості продажів |

## 3. Нефункціональні вимоги

| ID | Категорія | Вимога |
|---|---|---|
| NFR-1 | Безпека | Усі запити до БД через підготовлені вирази (захист від SQL-ін'єкцій), екранування даних при виведенні |
| NFR-2 | Продуктивність | Пошук і фільтрація до 1 секунди |
| NFR-3 | Супроводжуваність | Поділ на шари: представлення / бізнес-логіка / доступ до даних |

## 4. Обмеження

- Мова розробки: PHP 8+, середовище запуску: XAMPP (Apache).
- Сховище даних: SQLite (локальний файл).
- На першій версії немає авторизації користувачів.
- Мова інтерфейсу: українська.
- Розробка ведеться у Git-репозиторії з обов'язковим README.

## 5. Очікувані результати

- Працюючий вебзастосунок із функціями з розділу 2.
- Автоматизовані unit-тести основної бізнес-логіки.
- Документація: SRS, backlog, use case diagram, UML-діаграми .
